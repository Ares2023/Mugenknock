# Jev 実験データ（2026-09-30）

検証(02)のトリアージに Jev を使えるか、精度を上げられるかを実測したときの生データと再現スクリプト。
結論と採用した設計は [docs/07-operations.md](../../../../../docs/07-operations.md) の
「検証（02）の選定順位と Jev トリアージ」。ここは**根拠の生データ置き場**。

## 何が入っているか

| ディレクトリ | 内容 |
|---|---|
| `discovery/` | 精度改善実験の**探索データ**（positive 100 / negative 100）。改善案を試した母集団 |
| `holdout/` | **未見データ**（別の 100 / 100、探索と重複 0 件）。事前に固定した1候補を現行と比較した |
| `scripts/` | 収集 `collect.py`・分析 `analyze.py` / `analyze3.py`・未見検証 `holdout.py`・静的解析との比較 `static_vs_jev.py` |
| `round1/` | 最初の評価ラウンド（n=45〜60）の結果とスクリプト。**結論の一部は後の追試で訂正された**（下記） |

各データセットのファイル:

| ファイル | 内容 |
|---|---|
| `items_meta.json` | 問題ID・ラベル（1=Claudeが修正した / 0=okだった）・修正された項目（`kinds`）・修正理由 |
| `items_q.json` | 評価に使った問題本体。**positive は修正前の状態に復元済み**（`validityEditLog` の `before`） |
| `cache/<構成>.json` | Jev の生スコア（問題ID → スコア）。構成名は下表 |
| `fewshot_used.json` | few-shot 構成に使った例（評価に使わない修正から採取） |

`cache/` の構成:

| 構成 | 内容 |
|---|---|
| `base` / `base_r` | 現行（hint_leak + factual_error を1コール・全 state）と、その再実行 |
| `sep_hint` | hint_leak を1質問・選択肢のみで **← 採用した構成** |
| `sep_fact` | factual_error を1質問で |
| `fs_hint` | few-shot 例つきの hint_leak |
| `c3` | `choice` タイプ（clean / legit / leak） |
| `abbr` / `over` / `ce` | 略語未展開 / 選択肢の過剰説明 / 選択肢別解説のズレ |

`holdout/cache/` は `base` / `sep_hint` / `abbr` のみ（事前固定した候補の検証に必要な分）。

## データセットの作り方

- 母集団: DynamoDB `Questions` の非公開でない問題のうち `validityCheckedAt >= 2026-08-20`。
  選択肢の括弧ルールが入った日（コミット e5b3630）で切る。それ以前の「ok」は現行ルールでは
  要修正でありうるためラベルノイズになる。
- positive: `validityEditLog` に修正記録がある（Claude が直した）。`changes.*.before` で修正前に復元して投入。
- negative: 修正記録がない（Claude が ok と判定した）。
- 乱数シード 101。探索 = 先頭100件、未見 = 101〜200件目（`OFFSET=100`）。
- **domain 未設定の補完（`None→int`）が理由の正例は分析時に除外する**（`EXCL_DOMAIN_FILL=1`）。
  本番のプールにもう無い欠陥種で、Jev には不当に低く・決定的特徴には不当に高く出て評価を歪める。
  除外後は探索 88 / 100、未見 86 / 100。
- 問題ダンプ（35MB）は保存していない。使った問題は `items_q.json` に凍結してあるので、
  DB が変わっても再現できる。

## 再現

```bash
cd prompts/night-prompts/scripts/jev-experiments/2026-09-30
python3 scripts/analyze3.py     # 探索データ: 単純な組み合わせを現行と比較（保存済みスコアのみ・Jev は呼ばない）
python3 scripts/holdout.py      # 未見データ: 事前固定した候補 vs 現行
EXCL_DOMAIN_FILL=1 python3 scripts/analyze.py   # 探索データの全分析（AUC+CI・欠陥種別・交差検証・効率）
```

いずれも保存済みスコアだけで動く（Jev を呼ばず費用ゼロ）。数値はそのまま再現できることを確認済み。
新しくスコアを集め直す場合のみ `collect.py`（要 `QUESTIONS_DUMP` と Jev の API キー、費用が発生）。

## 結果の要約

| 観点（domain補完除外） | 探索 | 未見 | 備考 |
|---|---|---|---|
| 現行 max(hint, fact)・全 state | 0.761 | 0.794 | 2質問を1コール |
| **hint_leak・選択肢のみ・1質問** | **0.803** | **0.836** | 両方で現行比 +0.042。プールで **+0.043 [+0.011, +0.075]** |
| abbr（略語未展開） | 0.676 | **0.541** | 探索では効いて見えたが未見で再現せず |
| 事前固定 `mean(sep_hint, abbr, 括弧率)` | 0.824 | 0.788 | 現行比 −0.006（未見） |
| 2回平均 | −0.005 | ― | ノイズはボトルネックではない |
| few-shot / choice タイプ | 0.795 / 0.775 | ― | 単独コールを上回らず |

効率（プール30・上位10・有病率38%、ランダム=1.00）: 現行 1.54 → 採用構成 1.67（探索・帯幅0.25）。
未見では 1.71 → 1.84。連続値なら 1.82 / 1.92。

## 静的解析との比較（`scripts/static_vs_jev.py`）

Jev は静的ルールで代替できるか。静的側にも探索→未見の手順を踏ませて比べた（Jev を呼ばず費用ゼロで再現できる）。
静的ルール = 「数字を含まない括弧を持つ選択肢の割合」。

| | 探索 | 未見 |
|---|---|---|
| 全体 AUC: Jev / 静的 | 0.803 / 0.780 | 0.836 / 0.778 |
| 括弧のある問題だけの AUC: Jev / 静的 | 0.785 / 0.735 | 0.749 / 0.595 |
| 欠陥検出数/バッチ（帯0.25）: Jev / 静的 | 19.0 / 20.2 | 21.0 / 20.2 |
| 欠陥検出数/バッチ（帯0.1）: Jev / 静的 | 20.5 / 20.5 | 21.9 / 20.2 |

- Jev は括弧のある問題の切り分けで静的より上（プール差 +0.03〜+0.17）。全体 AUC でも約 +0.04 上。
- ただし運用の欠陥検出数は、帯0.25（日付優先）では差なし。帯を細かくすると Jev が約 +0.8 件/バッチ（約4%）。
- Jev と静的の平均は Jev 単独より良くならない。
- 意味的な欠陥（事実誤り・正解の当否・解説のズレ）は Jev も判定できず、静的でできないことを Jev がやれてはいない。

## 読むときの注意

- **round1 の数値は n=45〜60 で 95%CI が ±0.1 ある。** 例えば hint_leak 0.901 は楽観的で、
  n=約190 では 0.82 だった。差を語れるのは `discovery/` `holdout/` 以降。
- **round1 の `domain_wrong` の AUC 1.000 はラベルリーク**（domain 未設定の検出だっただけ）。
- **round1 の合成 `max(hint_leak, factual_error)` = 0.763 / 0.775 は採用していない。**
  factual_error は足しても改善しなかったため、最終構成は hint_leak 単独。
- **ラベル自体にノイズがある。** Claude の括弧の扱いが一貫しない例:
  `サービスマップ（Service Map）` は残されたが `グローバルテーブル（Global Tables）` は削除された
  （`fewshot_used.json`）。AUC の上限を押し下げている。
- `round1/` のスクリプトは `/tmp` を直書きしていて、そのままでは動かない（記録用）。
- 事後に多数の候補を見て選ぶと偽の改善が出る（abbr がその例）。改良案は事前に1つに固定し、
  未見データで現行と比較すること。
