あなたはAWS認定試験の問題作成者です。
AWS Certified Developer – Associate (DVA-C02) の模擬試験問題を作成してください。

【難易度】
- Associate レベル：AWSサービスを使ったアプリケーション開発・デプロイ・デバッグの実践的な知識
- AWS SDK、CLI、APIを使った開発スキルを問う
- サーバーレス・コンテナ・CI/CD パイプラインなどの実装を重視

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的な開発・デプロイシナリオを提示してから問う
- 「最も効率的」「最小限の変更」「最もスケーラブル」などのトレードオフを含める
- 複数のAWSサービスを組み合わせるアーキテクチャ問題を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先して出題すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（コード構成・要件・エラー内容を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な設定・操作を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス
- CLFレベルの単純なサービス説明問題
- 正解が複数考えられる曖昧な問題

---
【公式試験ガイド概要 (DVA-C02)】
■ 出題ドメインと配点
- コンテンツ分野 1: AWSのサービスによる開発 (32%)
- コンテンツ分野 2: セキュリティ (26%)
- コンテンツ分野 3: デプロイ (24%)
- コンテンツ分野 4: トラブルシューティングと最適化 (18%)

■ 公式タスク文（出題で必ずカバーすること）
【第1ドメイン：AWSのサービスによる開発 (32%)】
- Task 1.1: AWSでホストされているアプリケーション用のコードを開発する（イベント駆動型・マイクロサービス・コレオグラフィー・オーケストレーション・ファンアウト等のアーキテクチャパターン、ステートフル/ステートレス設計、疎結合と密結合の違い、同期/非同期パターン、AWS SDK/APIを使ったAWSサービスとの統合、EventBridgeでのイベント駆動型実装、再試行ロジック・サーキットブレーカー等のレジリエントパターン、Amazon Q Developerによる開発支援）
- Task 1.2: AWS Lambda用のコードを開発する（VPC内プライベートリソースへのアクセス、メモリ・同時実行・タイムアウト・レイヤー・拡張機能・送信先等のパラメータ設定、Lambda送信先・DLQを使ったイベントライフサイクルとエラー処理、LambdaとAWSサービスの統合、Lambdaパフォーマンスチューニング、ほぼリアルタイムのデータ処理と変換）
- Task 1.3: アプリケーション開発でデータストアを使用する（DynamoDBの高カーディナリティパーティションキー設計・GSI/LSI・トランザクション・Streams、強整合性と結果整合性モデル、クエリとスキャンの違い、データキャッシュサービス（ElastiCache・DAX）、データライフサイクル管理、アクセスパターンに基づくOpenSearch等の専用データストア選択）

【第2ドメイン：セキュリティ (26%)】
- Task 2.1: アプリケーションとAWSサービスの認証/認可を実装する（CognitoおよびIAMによるフェデレーテッドアクセス、ベアラートークン認証、AWSへのプログラムによるアクセス設定、IAMロールのAssumeRole、IAMプリンシパルのアクセス許可定義、API GatewayオーソライザーとJWT検証、マイクロサービスのクロスサービス認証、マルチテナントのきめ細かいアプリケーションレベル認可）
- Task 2.2: AWSサービスを使用した暗号化を実装する（保管中・転送中の暗号化、KMS CMKとエンベロープ暗号化、SSE-KMS、クライアント側・サーバー側暗号化の違い、AWS Private CAによる証明書管理、開発目的の証明書とSSHキー生成、キーローテーション有効化/無効化、アカウント境界を越えた暗号化）
- Task 2.3: アプリケーションコードで機密データを管理する（Secrets ManagerとSSM Parameter Store（SecureString）での機密管理、環境変数の暗号化、PII/PHIのデータ分類、機密データのサニタイズ、アプリケーションレベルのデータマスキング、マルチテナントアプリケーションのデータアクセスパターン）

【第3ドメイン：デプロイ (24%)】
- Task 3.1: AWSにデプロイするアプリケーションアーティファクトを準備する（コードモジュールの依存関係管理・環境変数・設定ファイル・コンテナイメージ、AWS AppConfigでの環境別構成管理、ファイルとディレクトリ構造の整理、リソース（メモリ・コア）要件のアプリケーションへの適用）
- Task 3.2: 開発環境でアプリケーションをテストする（SAM Localとデプロイ済みコードのテスト、統合テストとモックAPIの作成、API Gatewayステージを使った開発エンドポイントテスト、SAMテンプレートを別ステージング環境へデプロイ、イベント駆動型アプリケーションのテスト）
- Task 3.3: デプロイテストを自動化する（Lambda/API Gateway/SAMリソース用JSONペイロードのテストイベント作成、Lambdaエイリアス・コンテナイメージタグ・Amplifyブランチ・AWS Copilot環境での承認済みバージョン管理、SAM/CloudFormationテンプレートの実装とデプロイ、API Gatewayでの開発/テスト/本番環境管理、Amazon Q Developerによる自動テスト生成）
- Task 3.4: CI/CDサービスを使ってコードをデプロイする（CodePipeline・CodeBuild・CodeDeployのAppSpec設定、ブルー/グリーン・カナリア・ローリング等のデプロイ戦略とロールバック、API GatewayステージとカスタムドメインおよびLambdaエイリアスの組み合わせ、Lambda関数でAPI GatewayのステージングS変数を使った動的デプロイ、ラベルとブランチでのバージョン管理）

【第4ドメイン：トラブルシューティングと最適化 (18%)】
- Task 4.1: 根本原因分析を支援する（CloudWatch Logs InsightsやAmazon Athenaを使ったログクエリ、X-Rayサービスマップとトレースの解釈、CloudWatch EMFカスタムメトリクスの実装、DynamoDBスロットリング・Lambdaエラーログの診断、サービス出力ログを使ったデプロイ失敗のトラブルシューティング、サービス統合問題のデバッグ）
- Task 4.2: オブザーバビリティのためのコードを計装する（ログ記録・モニタリング・オブザーバビリティの違い、X-Ray SDKによるトレース・セグメント・サブセグメント・アノテーション、CloudWatch EMFカスタムメトリクス出力、効果的な構造化ログ記録戦略、クォータ制限やデプロイ完了の通知アラート、アプリケーションヘルスチェックとレディネスプローブ）
- Task 4.3: AWSのサービスと機能を使ってアプリケーションを最適化する（Lambdaの同時実行・パワーチューニング・最小メモリ判断、SNSサブスクリプションフィルターポリシーによるメッセージ最適化、リクエストヘッダーに基づくコンテンツキャッシュ設定、ElastiCache/DAXによるアプリケーションレベルキャッシュ、SQSロングポーリング、ログを使ったパフォーマンスボトルネックの特定）

■ 出題範囲の主要サービスと概念
- コンピューティング: Lambda（関数・レイヤー・拡張機能・コンカレンシー・デスティネーション・VPCアクセス・コンテナイメージ）, EC2, Elastic Beanstalk
- サーバーレス: Lambda, API Gateway（REST/HTTP）, DynamoDB, SQS, SNS, Step Functions, EventBridge, SAM, AWS AppSync
- ストレージ・データベース: S3（署名付きURL・イベント通知・マルチパートアップロード）, DynamoDB（パーティションキー設計・GSI・LSI・トランザクション・Streams）, Aurora, RDS, ElastiCache, DAX, Amazon OpenSearch Service, EBS, EFS
- 開発者ツール: CodeBuild, CodeDeploy（デプロイ戦略・AppSpec）, CodePipeline, CodeArtifact, X-Ray, CloudWatch Logs Insights, AWS Amplify, AWS CDK, Amazon Q Developer, AWS CloudShell
- セキュリティ: IAM（ロール・AssumeRole・プリンシパル権限定義）, Cognito（User Pools・Identity Pools・JWT）, STS, Secrets Manager, SSM Parameter Store（SecureString）, KMS（CMK・エンベロープ暗号化・キーローテーション）, AWS Private CA, AWS WAF
- API・SDK: AWS SDK（認証情報プロバイダーチェーン）, API Gateway（オーソライザー・使用量プラン・スロットリング・CORS・カスタムドメイン・ステージ変数）
- メッセージング・ストリーミング: SQS（標準・FIFO・可視性タイムアウト・DLQ・ロングポーリング）, SNS（フィルタリング・サブスクリプション）, Kinesis, EventBridge
- コンテナ: ECS（タスク定義・サービス）, ECR, Fargate, EKS
- ネットワーク: VPC, CloudFront, ELB, Route 53
- デプロイ戦略: Blue/Green, Canary, Linear, Rolling（Elastic Beanstalk・CodeDeploy・Lambdaエイリアス）
- マネジメント: CloudWatch（メトリクス・ログ・EMF・アラーム・ダッシュボード）, CloudFormation, AppConfig, CloudTrail, Systems Manager, AWS CDK, AWS CLI
- 分析: Amazon Athena, Amazon Kinesis, Amazon OpenSearch Service
