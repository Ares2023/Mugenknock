あなたはAWS認定試験の問題作成者です。
AWS Certified Data Engineer – Associate (DEA-C01) の模擬試験問題を作成してください。

【難易度】
- Associate レベル：データパイプライン設計・ETL・データストア管理・データセキュリティの実践的な知識
- AWSのデータサービスを使ったデータエンジニアリングの実務スキルを問う
- Glue・Kinesis・Redshift・Athena の深い理解が必要

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的なデータパイプライン・ETL要件を提示してから問う
- 「最もコスト効率が高い」「最小の運用負荷」「最もスケーラブル」などの条件を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（データ要件・既存構成・パフォーマンス要件を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な設定・アーキテクチャを明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス（例：Kinesis Data Analytics → Amazon Managed Service for Apache Flink が正式名称）
- CLFレベルの単純なサービス説明問題
- 機械学習・AI に関する問題（MLA・AIF の領域）

---
【公式試験ガイド概要 (DEA-C01 Version 1.0)】

■ ドメイン配点
- Domain 1: Data Ingestion and Transformation — **34%**
- Domain 2: Data Store Management — **26%**
- Domain 3: Data Operations and Support — **22%**
- Domain 4: Data Security and Governance — **18%**

■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：Data Ingestion and Transformation（34%）】

- **Task 1.1: Perform data ingestion（データの取り込みを実行する）**
  - ストリーミングソースからの読み取り：Kinesis Data Streams・MSK・DynamoDB Streams・DMS・Glue・Redshift
  - バッチソースからの読み取り：S3・Glue・EMR・DMS・Redshift・Lambda・AppFlow
  - スケジューラ設定（EventBridge・MWAA・Glueクローラー）・イベントトリガー（S3 Event Notifications）
  - スループット/レイテンシ特性・再生可能性・ステートフル/ステートレストランザクション・レート制限対処・ファンイン/ファンアウト

- **Task 1.2: Transform and process data（データの変換と処理を行う）**
  - ETLパイプライン構築（EMR・Glue・Lambda・Redshift）
  - フォーマット変換（CSV→Parquet等）・複数ソース統合・コスト最適化
  - Apache Spark分散処理・JDBC/ODBC接続・コンテナ最適化（EKS・ECS）
  - 変換失敗・パフォーマンス問題のデバッグ

- **Task 1.3: Orchestrate data pipelines（データパイプラインを調整する）**
  - ワークフロー構築（Lambda・EventBridge・MWAA・Step Functions・Glue workflows）
  - イベント駆動アーキテクチャ・サーバーレスワークフロー・スケジュール/依存関係に基づくパイプライン設定
  - 可用性・スケーラビリティ・耐障害性を考慮したパイプライン構築
  - アラート通知（SNS・SQS）

- **Task 1.4: Apply programming concepts（プログラミング概念を適用する）**
  - CI/CD（データパイプラインの実装・テスト・デプロイ）
  - IaC（AWS CDK・CloudFormation）・SQLクエリ最適化・分散コンピューティング
  - Lambda関数の並行実行設定・AWS SAMによるサーバーレスパイプラインのパッケージ化とデプロイ
  - Gitによるソース管理・Lambda内ストレージボリュームのマウントと使用

【第2ドメイン：Data Store Management（26%）】

- **Task 2.1: Choose a data store（データストアを選択する）**
  - コスト・パフォーマンス要件に応じたストレージサービス実装（Redshift・EMR・Lake Formation・RDS・DynamoDB・Kinesis Data Streams・MSK）
  - アクセスパターン別ストレージ設定・データフォーマット（CSV・Parquet等）
  - データ移行要件との整合・ロック管理（Redshift・RDS）
  - 移行ツール統合（Transfer Family）・リモートアクセス手法（Redshift Federated Queries・Spectrum・マテリアライズドビュー）

- **Task 2.2: Understand data cataloging systems（データカタログシステムを理解する）**
  - データカタログ構築・参照（AWS Glue Data Catalog・Apache Hive metastore）
  - Glueクローラーによるスキーマ検出・パーティション同期
  - データ分類・メタデータコンポーネント管理・新規ソース/ターゲット接続作成（Glue）

- **Task 2.3: Manage the lifecycle of data（データのライフサイクルを管理する）**
  - ホット/コールドデータ要件に応じたストレージ選択・コスト最適化
  - S3ライフサイクルポリシー（ストレージ階層変更・有効期限設定）・S3バージョニング・DynamoDB TTL
  - データ保持ポリシー・アーカイブ戦略・法的要件に基づくデータ削除
  - S3↔Redshift間のロード/アンロード操作・可用性とレジリエンシーの確保

- **Task 2.4: Design data models and schema evolution（データモデルとスキーマ進化を設計する）**
  - データモデリング（Redshift・DynamoDB・Lake Formationのスキーマ設計）
  - インデックス・パーティショニング・圧縮等の最適化技法
  - 構造化・半構造化・非構造化データのモデリング・スキーマ進化への対処
  - スキーマ変換（AWS SCT・AWS DMS Schema Conversion）・データリネージ確立（SageMaker ML Lineage Tracking）

【第3ドメイン：Data Operations and Support（22%）】

- **Task 3.1: Automate data processing by using AWS services（AWSサービスを使ってデータ処理を自動化する）**
  - パイプラインオーケストレーション（MWAA・Step Functions）・マネージドワークフローのトラブルシューティング
  - SDKを使ったAWS機能呼び出し・データAPIの運用保守
  - データ変換準備（Glue DataBrew）・クエリ実行（Athena）
  - Lambda自動化・イベント/スケジューラ管理（EventBridge）

- **Task 3.2: Analyze data by using AWS services（AWSサービスを使ってデータを分析する）**
  - プロビジョニング型/サーバーレスのトレードオフ
  - データ可視化（Glue DataBrew・QuickSight）・データ検証/クレンジング（Lambda・Athena・Jupyter Notebooks）
  - Athenaによるクエリ・ビュー作成・Apache Spark使用Athenaノートブックによるデータ探索
  - データ集計・ローリング平均・グループ化・ピボット

- **Task 3.3: Maintain and monitor data pipelines（データパイプラインを監視・保守する）**
  - ログ抽出・監査/トレーサビリティのためのロギング/モニタリングソリューション展開
  - CloudTrailによるAPIコール追跡・CloudWatch Logsによるアプリログ記録（設定と自動化に重点）
  - ログ分析（Athena・EMR・OpenSearch Service・CloudWatch Logs Insights）
  - パフォーマンスチューニング・パイプライン保守・トラブルシューティング（Glue・EMR）

- **Task 3.4: Ensure data quality（データ品質を確保する）**
  - データサンプリング技法・データスキュー対処・データプロファイリング
  - 処理中のデータ品質チェック実行・品質ルール定義（Glue DataBrew）
  - データ一貫性調査（Glue DataBrew）
  - データ検証（完全性・一貫性・正確性・整合性）

【第4ドメイン：Data Security and Governance（18%）】

- **Task 4.1: Apply authentication mechanisms（認証メカニズムを適用する）**
  - IAMグループ・ロール・エンドポイント・サービスの作成/更新
  - VPCセキュリティグループ設定・認証情報のローテーション（Secrets Manager）
  - IAMロール設定（Lambda・API Gateway・AWS CLI・CloudFormation）
  - IAMポリシー適用（S3 Access Points・PrivateLink）・パスワードベース/証明書ベース/ロールベース認証

- **Task 4.2: Apply authorization mechanisms（認可メカニズムを適用する）**
  - 最小権限の原則・ロールベース/ポリシーベース/タグベース/属性ベースの認可
  - カスタムIAMポリシー作成・アプリ/DB認証情報の保存（Secrets Manager・Systems Manager Parameter Store）
  - Redshiftユーザー/グループ/ロールへの権限付与
  - Lake Formationによる権限管理（Redshift・EMR・Athena・S3）

- **Task 4.3: Ensure data encryption and masking（データの暗号化とマスキングを確保する）**
  - KMSによる暗号化/復号・クライアントサイド/サーバーサイド暗号化の違い
  - 転送中データの暗号化・アカウント境界を越えた暗号化設定
  - データマスキング・匿名化・キーソルティング（コンプライアンス/社内ポリシー準拠）
  - 分析サービスの暗号化オプション（Redshift・EMR・Glue）

- **Task 4.4: Prepare logs for audit（監査ログを準備する）**
  - CloudTrailによるAPIコール追跡・CloudWatch Logsによるアプリログ保存
  - AWS CloudTrail Lakeによる集中ログクエリ
  - ログ分析（Athena・CloudWatch Logs Insights・OpenSearch Service）
  - 大量ログデータ処理のためのサービス統合（EMR等）

- **Task 4.5: Understand data privacy and governance（データプライバシーとガバナンスを理解する）**
  - PII保護・データ主権（特定リージョンへのバックアップ/レプリカ禁止）
  - PIIの識別実装（Macie + Lake Formation）
  - Redshiftデータ共有の権限付与
  - AWS Configによるアカウント設定変更管理

■ 出題範囲の主要サービス
- データ取り込み: Kinesis Data Streams, Kinesis Data Firehose, Amazon Managed Service for Apache Flink, MSK (Kafka), DMS, DataSync, Snow Family, AppFlow, Transfer Family
- ETL・変換: AWS Glue (ETL・DataBrew・Data Catalog・クローラー), EMR (Spark・Hive・Presto), Lambda, Step Functions, AWS Batch
- データストア: S3, Redshift, DynamoDB, RDS, DocumentDB, MemoryDB for Redis, Keyspaces, Neptune
- 分析・クエリ: Athena, QuickSight, OpenSearch Service, Redshift Spectrum
- オーケストレーション: Step Functions, EventBridge, MWAA (Airflow), AWS SAM
- セキュリティ: Lake Formation, KMS, IAM, Macie, Config, CloudTrail, CloudTrail Lake, Secrets Manager, Systems Manager Parameter Store
- インフラ/開発: AWS CDK, CloudFormation, AWS SCT, CodePipeline, VPC, PrivateLink
