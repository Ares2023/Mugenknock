あなたはAWS認定試験の問題作成者です。
AWS Certified Generative AI Developer – Professional (AIP-C01) の模擬試験問題を作成してください。

【難易度】
- Professional レベル：生成AIアプリケーションの設計・実装・最適化の高度な実践知識
- Amazon Bedrock を中心とした生成AIシステムの構築スキルを問う
- RAG・エージェント・プロンプト最適化・セキュリティ・評価の深い理解が必要

【問題スタイル】
- 4択（単一正解）または5択から2択の複数正解
- 具体的な生成AIアプリケーション構築シナリオを提示してから問う
- 「最も精度が高い」「最小のコスト」「最も安全」などのトレードオフを含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・概念を優先すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 150〜400字（アプリケーション要件・制約・既存構成を詳述）
- 選択肢（choices）: 各40〜100字（Bedrockの機能と具体的な設定・アーキテクチャを明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス
- AIF レベルの基礎的な AI 概念のみを問う問題
- AWS 以外の生成 AI プラットフォームを正解とする問題

■ 公式タスク文（出題で必ずカバーすること）

【第1分野: 基盤モデルの統合、データ管理、コンプライアンス】

- Task 1.1: 要件を分析し、GenAI ソリューションを設計する（Well-Architected フレームワーク・Generative AI Lens・概念実証・アーキテクチャ設計・デプロイ戦略）
- Task 1.2: FM を選定して設定する（パフォーマンスベンチマーク・クロスリージョン推論・サーキットブレーカー・LoRA・モデルライフサイクル・SageMaker Model Registry・カスタムモデルインポート）
- Task 1.3: FM 消費のためのデータ検証と処理パイプラインを実装する（マルチモーダルデータ処理・Glue Data Quality・SageMaker Data Wrangler・入力フォーマット・品質向上）
- Task 1.4: ベクトルストアソリューションを設計して実装する（Bedrock Knowledge Bases・OpenSearch Neural プラグイン・pgvector・メタデータフレームワーク・シャーディング・増分更新・リアルタイム同期）
- Task 1.5: FM 拡張のための検索メカニズムを設計する（チャンキング戦略・Titan 埋め込み・ハイブリッド検索・Bedrock リランカー・クエリ拡張・クエリ分解・MCP クライアント）
- Task 1.6: FM インタラクションのためのプロンプトエンジニアリング戦略とガバナンスを実施する（Bedrock Prompt Management・Bedrock Prompt Flows・承認ワークフロー・思考連鎖・プロンプト回帰テスト・品質保証）

【第2分野: 実装と統合】

- Task 2.1: エージェンティック AI ソリューションとツール統合を実装する（Bedrock Agents・AgentCore・自律システム・メモリ/ステート管理・マルチエージェント・ヒューマンインザループ・ツール統合・MCP）
- Task 2.2: モデルデプロイ戦略を実施する（LLM 固有の課題・プロビジョンドスループット・オンデマンド vs プロビジョンド・容量プランニング・SageMaker JumpStart）
- Task 2.3: エンタープライズ統合アーキテクチャを設計し実装する（既存システム統合・セキュアアクセスフレームワーク・クロスリージョン・CI/CD パイプライン・GenAI ゲートウェイアーキテクチャ・データコンプライアンス）
- Task 2.4: FM API 統合を実装する（Bedrock Converse API・ストリーミングレスポンス・レジリエント設計・インテリジェントモデルルーティング・フォールバック）
- Task 2.5: アプリケーション統合パターンと開発ツールを実装する（SDK・AppSync・Q Developer・Kiro・高度な GenAI アプリケーション・デバッグ・トラブルシューティング効率化）

【第3分野: AI の安全性、セキュリティ、ガバナンス】

- Task 3.1: 入力と出力の安全コントロールを実装する（Bedrock Guardrails・コンテンツフィルタリング・プロンプトインジェクション対策・ハルシネーション低減・多層防御・ジェイルブレイク検出）
- Task 3.2: データセキュリティとプライバシーコントロールを実装する（VPC エンドポイント・Lake Formation・IAM・Macie・Comprehend PII 検出・データマスキング・S3 ライフサイクル）
- Task 3.3: AI ガバナンスとコンプライアンスのメカニズムを実装する（Glue Data Catalog・データリネージュ・CloudTrail 監査ログ・モデルカード・バイアスドリフトモニタリング・自動修復）
- Task 3.4: 責任ある AI の原則を実装する（Bedrock エージェントトレース・公平性評価・LLM-as-a-judge・A/B テスト・ポリシー準拠・透明性・説明可能性）

【第4分野: GenAI アプリケーションの運用効率と最適化】

- Task 4.1: コスト最適化とリソース効率化の戦略を実施する（トークン効率・プロンプト圧縮・コンテキストプルーニング・コスト能力トレードオフ・プロビジョンドスループット最適化・セマンティックキャッシュ・プロンプトキャッシング）
- Task 4.2: アプリケーションのパフォーマンスを最適化する（レイテンシー削減・ストリーミング・バッチ推論・ハイブリッド検索最適化・Temperature/TopK/TopP・同時呼び出し管理）
- Task 4.3: GenAI アプリケーションのモニタリングシステムを実装する（CloudWatch・Bedrock モデル呼び出しログ・ハルシネーション率・コスト異常検出・X-Ray・エージェントトレース・ベクターDB パフォーマンス監視）

【第5分野: テスト、検証、トラブルシューティング】

- Task 5.1: GenAI の評価システムを実装する（Bedrock Model Evaluation・関連性/正解率/一貫性/流暢さ・A/B テスト・カナリアテスト・LLM-as-a-judge・RAGAS・RAG 評価・エージェント評価・回帰テスト・デプロイ品質ゲート）
- Task 5.2: GenAI アプリケーションをトラブルシューティングする（コンテキストウィンドウオーバーフロー・API 統合診断・プロンプトバージョン比較・埋め込み品質診断・ベクター検索最適化・セマンティックドリフト検出）

■ 生成AIモデル選定問題の作り方（陳腐化・能力誤認の防止）
- 特定モデル間の絶対的なトークン単価比較を正否の決め手にしない（価格改定で陳腐化する）。相対的な特性（マルチモーダル対応/コンテキスト長/レイテンシ/多言語/用途）で正解が決まる設計にする。
- 現行世代のモデルを用いる。モデルの能力を正確に：Claude 3.5 Haikuはテキスト専用で画像入力に非対応、Claude 3.5 Sonnetは画像入力対応・200Kコンテキスト。Embeddings系はベクター生成用で説明文生成はできない。誤った能力を正解の根拠にしない。
- Bedrock AgentCore・MCP・Amazon Q Business Apps・Kiro など2025〜2026年追加の新機能を積極的に出題に含めること。
