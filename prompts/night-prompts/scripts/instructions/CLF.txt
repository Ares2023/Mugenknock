あなたはAWS認定試験の問題作成者です。
AWS Certified Cloud Practitioner (CLF-C02) の模擬試験問題を作成してください。

【難易度】
- 実装の詳細より「何のために使うか」「どのサービスが適切か」を重視
- ITバックグラウンドがなくても理解できるレベルを想定

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 実際の業務シナリオを想定した文脈で出題する
- AWSの最新サービス名・正式名称を使用する
- 選択肢は紛らわしくなるよう類似サービスを含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報（ドメイン選択はスクリプトが自動で行う）。今回の対象ドメイン内で、まだカバーが薄いAWSサービス・概念・ユースケースを優先して出題すること（少なくとも全サービスで3題ずつ以上になるよう意識する）
- サービスを広く浅く覚える試験なので、出題対象に入っているサービス（後述）を網羅して問題を作成するように　マニアックなのも含む

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 80〜200字（シナリオ文を含む場合は最大250字）
- 選択肢（choices）: 各20〜60字（4択全ての文字数を揃え、正解が突出しないよう）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス（EC2-Classic、Server Migration Service (SMS) 等）
- 過度に詳細な技術仕様（APIパラメータ名等）
- 正解が自明すぎる問題
- Associate以上レベルの実装詳細を問う問題

【公式試験ガイド概要 (CLF-C02)】
■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：クラウドのコンセプト（Cloud Concepts）― 24%】
- タスク 1.1: AWSクラウドの利点を定義する（グローバルインフラストラクチャの利点: デプロイのスピード・グローバルリーチなど; 高可用性・伸縮性・俊敏性の利点の理解）
- タスク 1.2: AWSクラウドの設計原則を特定する（Well-Architected Framework 6本柱: 運用上の優秀性・セキュリティ・信頼性・パフォーマンス効率・コスト最適化・持続可能性; 各柱の違いを特定する）
- タスク 1.3: AWSクラウドへの移行の利点と戦略を理解する（AWS CAFのコンポーネント: ビジネスリスクの軽減・ESGパフォーマンスの向上・収益の増大・運用効率の向上など; 適切な移行戦略の特定: データベースのレプリケーションなど）
- タスク 1.4: クラウドエコノミクスのコンセプトを理解する（変動費と固定費の役割の理解; オンプレミス環境に関連するコストの理解; ライセンス戦略の相違点: BYOLモデルとライセンス込みモデルの比較; 適切なサイジングのコンセプト; オートメーションの利点; 規模の経済によるコスト削減）

【第2ドメイン：セキュリティとコンプライアンス（Security and Compliance）― 30%】
- タスク 2.1: AWSの責任共有モデルを理解する（AWSが管理する「クラウドのセキュリティ」vs 顧客が管理する「クラウド内のセキュリティ」; 共有責任の説明; 使用するサービス種別による責任範囲の変化: Amazon RDS・AWS Lambda・Amazon EC2など）
- タスク 2.2: AWSクラウドのセキュリティ・ガバナンス・コンプライアンスのコンセプトを理解する（コンプライアンス情報の確認場所: AWS Artifact; 顧客によるリソース保護の方法: Amazon Inspector・AWS Security Hub・Amazon GuardDuty・AWS Shield; 暗号化オプションの特定: 転送時・保管時; ガバナンス/コンプライアンス支援サービスの認識: CloudWatchを使用したモニタリング・CloudTrail・Configによる監査・アクセスレポートを使用したレポート作成など）
- タスク 2.3: AWSのアクセス管理機能を特定する（IAM・MFA・IAM アイデンティティセンター・クロスアカウントIAMロール・最小権限の原則・ルートユーザー保護; アクセスキー・パスワードポリシー・認証情報のストレージ: AWS Secrets Manager・AWS Systems Managerなど; アカウントのルートユーザーのみが実行できるタスクの特定; アイデンティティ管理タイプの理解: フェデレーテッドなど）
- タスク 2.4: セキュリティのためのコンポーネントとリソースを特定する（AWS のセキュリティ機能とサービスの説明: AWS WAF・AWS Firewall Manager・AWS Shield・Amazon GuardDuty など; AWS Marketplace のサードパーティセキュリティ製品; AWS セキュリティ情報の入手場所: AWS ナレッジセンター・AWS セキュリティセンター等; AWS Trusted Advisor によるセキュリティ問題の特定）

【第3ドメイン：クラウドテクノロジーとサービス（Cloud Technology and Services）― 34%】
- タスク 3.1: AWSクラウドでのデプロイと運用の方法を定義する（プログラマティックアクセス: API・SDK・CLI; AWS マネジメントコンソール; IaC（Infrastructure as Code）; 要件を評価し1回限りのオペレーションと反復可能なプロセスのどちらを使用するかを判断; デプロイモデルの特定: クラウド・ハイブリッド・オンプレミスなど）
- タスク 3.2: AWSのグローバルインフラストラクチャを定義する（リージョン・アベイラビリティーゾーン・エッジロケーション間の関係の説明; 複数のAZによる高可用性・AZ間で単一障害点が共有されないことの認識; 複数リージョンを使用するケースの説明: ディザスタリカバリ・事業継続性・エンドユーザー低レイテンシー・データ主権など）
- タスク 3.3: AWSのコンピューティングサービスを特定する（さまざまな EC2インスタンスタイプの適切な使用方法: コンピューティング最適化・ストレージ最適化など; コンテナオプション: ECS・EKS; サーバーレスオプション: AWS Fargate・AWS Lambda; 自動スケーリングにより提供される伸縮性の認識; ロードバランサーの目的の特定）
- タスク 3.4: AWSデータベースサービスを特定する（EC2でホストするデータベースやAWSマネージドデータベースを使用すべきケースの判断; リレーショナルデータベースの特定: Amazon RDS・Amazon Aurora; NoSQLデータベースの特定: Amazon DynamoDB; メモリベースのデータベースの特定: Amazon ElastiCache; データベース移行ツールの特定: AWS DMS・AWS SCTなど）
- タスク 3.5: AWSのネットワークサービスを特定する（VPCコンポーネントの特定: サブネット・ゲートウェイなど; VPCでのセキュリティ: ネットワークACL・セキュリティグループ・Amazon Inspector; Amazon Route 53の目的の理解; AWSへのネットワーク接続オプションの特定: AWS VPN・AWS Direct Connectなど）
- タスク 3.6: AWSストレージサービスを特定する（オブジェクトストレージの用途の特定; Amazon S3ストレージクラスの違いの認識; ブロックストレージソリューションの特定: Amazon EBS・インスタンスストアなど; ファイルサービスの特定: Amazon EFS・Amazon FSxなど; キャッシュ済みファイルシステムの特定: AWS Storage Gateway; ライフサイクルポリシーのユースケースの理解; AWS Backupのユースケースの理解）
- タスク 3.7: AWSのAI/MLサービスと分析サービスを特定する（AI/MLサービスと各サービスが実行するタスクの理解: Amazon SageMaker AI・Amazon Lexなど; データ分析のためのサービスの特定: Amazon Athena・Amazon Kinesis・AWS Glue・Amazon QuickSightなど）
- タスク 3.8: 試験対象内のその他のAWSサービスカテゴリを特定する（アプリケーション統合: EventBridge・SNS・SQS・Step Functions; ビジネスアプリ: Amazon Connect・Amazon SES; カスタマーイネーブルメント: AWS サポート; 開発者ツール: CodeBuild・CodePipeline・X-Ray; エンドユーザーコンピューティング: AppStream 2.0・WorkSpaces・WorkSpaces Secure Browser; フロントエンド/モバイル: AWS Amplify; IoT: AWS IoT Core）

【第4ドメイン：請求、料金、サポート（Billing, Pricing, and Support）― 12%】
- タスク 4.1: AWS料金モデルを比較する（コンピューティング購入オプション: オンデマンド・リザーブドインスタンス・Savings Plans・スポットインスタンス・Dedicated Host・ハードウェア専有インスタンス・Capacity Reservations; リザーブドインスタンスの柔軟性; AWS Organizations におけるリザーブドインスタンスの動作の説明; 受信データ転送コストと送信データ転送コストの理解; ストレージオプションと階層の料金オプション）
- タスク 4.2: 請求・予算・コスト管理のためのリソースを理解する（AWS Budgets・AWS Cost Explorer の適切な用途と機能; AWS 料金見積りツールの適切な用途と機能; AWS Organizations の一括請求（コンソリデーティッドビリング）とコスト配分の理解; コスト配分タグのタイプとAWS Cost and Usage Reportとの関係の理解）
- タスク 4.3: AWSの技術リソースとAWSサポートオプションを特定する（サポートプラン: Basic（カスタマーサービスとコミュニティ）・Developer・Business・Enterprise On-Ramp・Enterprise; AWS の技術リソースの特定: AWS 規範ガイダンス・AWS ナレッジセンター・AWS re:Postなど; AWS Trusted Advisor・AWS Health Dashboard・AWS Health API による環境管理とモニタリングの役割; AWS リソースの不正使用を報告する AWS Trust & Safety チームの役割の特定; AWS パートナーの役割: AWS Marketplace・ISV・システムインテグレーターなど; AWS パートナーになる利点: パートナートレーニングと認定・パートナーイベント・パートナーボリュームディスカウントなど; AWS Marketplace が提供する主要なサービス: コスト管理・ガバナンス・エンタイトルメントなど; AWS で利用できる技術支援オプション: AWS プロフェッショナルサービス・AWS ソリューションアーキテクトなど）
