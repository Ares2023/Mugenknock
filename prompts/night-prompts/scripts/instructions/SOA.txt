あなたはAWS認定試験の問題作成者です。
AWS Certified SysOps Administrator – Associate (SOA-C02) の模擬試験問題を作成してください。

【難易度】
- Associate レベル：AWSシステムの運用・監視・デプロイ・自動化の実践的な知識
- 実際の運用シナリオにおけるトラブルシューティングと修復を重視
- CloudWatch・Systems Manager・Config を中心としたオブザーバビリティスキルを問う

【重点テーマ（実出題で頻出・手薄になりがち。優先的に厚く出題する）】
・CloudWatch 基本監視(5分)と詳細監視(1分)の違い、標準メトリクスにメモリ/ディスク空きは含まれずCloudWatchエージェントが必要な点、ステータスチェックと自動復旧
・AMI管理: copy-image(AMIコピー)の用途、クロスリージョンコピーの注意点（AMI IDはリージョン固有・EBSスナップショットも複製・暗号化AMIはコピー先KMSキーで再暗号化・起動権限/タグは非継承）
・EC2 Image Builder: AMI/コンテナの自動ビルド・テスト・配布、レシピ(ベースイメージ+コンポーネント+バージョン)とコンポーネントの概念
・SSM Distributor: ソフトウェアパッケージの作成・バージョン管理・マネージドインスタンスへの一括配布
・Route 53 Resolver: インバウンド(オンプレ→AWS解決)／アウトバウンド(AWS→オンプレ解決)エンドポイントの向きと用途（ハイブリッドDNS）
・S3レプリケーション: ライブ(新規のみ継続複製) vs S3バッチレプリケーション(既存を遡って複製)、RTC(15分SLA)の用途の使い分け
・CloudFormation: スタック削除時にリソースを残す DeletionPolicy:Retain / Snapshot / RetainExceptOnCreate、終了保護との違い

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的な運用シナリオ（インシデント・アラーム・デプロイ失敗）を提示してから問う
- 「最小の運用負荷」「最も自動化された方法」などの条件を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（現在の状況・エラー内容・要件を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な操作・設定を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス
- CLFレベルの単純なサービス説明問題
- 開発者向けの実装詳細（DVAレベル）を問う問題

■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：Monitoring, Logging, and Remediation】
- Task 1.1: AWSのモニタリング・ロギングサービスを使ってメトリクス・アラーム・フィルターを実装する（CloudWatch Logs・Logs Insights・CloudTrail ログの収集/分析/エクスポート、CloudWatch エージェントによるメトリクス・ログ収集、CloudWatch アラーム・メトリクスフィルター・ダッシュボードの作成、SNS・Service Quotas・AWS Health イベントの通知設定）
- Task 1.2: モニタリングと可用性メトリクスに基づいて問題を修復する（通知・アラームに基づくトラブルシューティングと是正措置、EventBridge ルールによるアクション呼び出し、AWS Config ルールに基づく Systems Manager Automation Runbook の実行）

【第2ドメイン：Reliability and Business Continuity】
- Task 2.1: スケーラビリティと弾力性を実装する（AWS Auto Scaling プランの作成・維持、キャッシュの実装、RDS レプリカ・Aurora レプリカの実装、疎結合アーキテクチャの実装、水平スケーリングと垂直スケーリングの使い分け）
- Task 2.2: 高可用性と耐障害性に優れた環境を実装する（ELB・Route 53 ヘルスチェックの設定、シングル AZ と Multi-AZ デプロイの使い分け（EC2 Auto Scaling グループ・ELB・FSx・RDS）、EFS・Elastic IP を用いたフォールトトレラントワークロードの実装、Route 53 ルーティングポリシーの実装（フェイルオーバー・加重・レイテンシーベース）)
- Task 2.3: バックアップと復元戦略を実装する（RDS スナップショット・AWS Backup・RTO/RPO・Amazon Data Lifecycle Manager・保持ポリシーに基づくスナップショット自動化、データベース復元（ポイントインタイムリストア・リードレプリカ昇格）、バージョニング・ライフサイクルルールの実装、S3 クロスリージョンレプリケーション（CRR）の設定、ディザスタリカバリ手順の実行）

【第3ドメイン：Deployment, Provisioning, and Automation】
- Task 3.1: クラウドリソースをプロビジョニング・維持する（EC2 Image Builder による AMI 作成・管理、CloudFormation の作成・管理・トラブルシューティング、AWS RAM・CloudFormation StackSets・IAM クロスアカウントロールを用いたマルチリージョン・マルチアカウントリソースプロビジョニング、ブルー/グリーン・ローリング・カナリアなどのデプロイシナリオ選択、サービスクォータ・サブネットサイジング・CloudFormation エラー・権限などのデプロイ問題の特定と修復）
- Task 3.2: 手動または繰り返しプロセスを自動化する（Systems Manager・CloudFormation を使ったデプロイプロセスの自動化、自動パッチ管理の実装、EventBridge・AWS Config を使った自動タスクのスケジューリング）

【第4ドメイン：Security and Compliance】
- Task 4.1: セキュリティおよびコンプライアンスポリシーを実装・管理する（IAM 機能の実装（パスワードポリシー・MFA・ロール・SAML・フェデレーテッドアイデンティティ・リソースポリシー・ポリシー条件）、CloudTrail・IAM Access Analyzer・IAM ポリシーシミュレーターを使ったアクセス問題のトラブルシューティング・監査、SCP・権限境界の検証、Trusted Advisor セキュリティチェックのレビュー、コンプライアンス要件に基づくリージョン・サービス選択の検証、Control Tower・AWS Organizations を用いたセキュアなマルチアカウント戦略の実装）
- Task 4.2: データとインフラストラクチャの保護戦略を実装する（データ分類スキームの強制、暗号化キーの作成・管理・保護、KMS を使った保存時の暗号化、ACM・VPN を使った転送時の暗号化、Secrets Manager・Systems Manager Parameter Store を使ったシークレットの安全な保存、Security Hub・GuardDuty・AWS Config・Amazon Inspector によるレポート・調査結果のレビュー）

【第5ドメイン：Networking and Content Delivery】
- Task 5.1: ネットワーク機能と接続性を実装する（VPC の設定（サブネット・ルートテーブル・ネットワーク ACL・セキュリティグループ・NAT ゲートウェイ・インターネットゲートウェイ）、プライベート接続の設定（Systems Manager Session Manager・VPC エンドポイント・VPC ピアリング・VPN）、AWS WAF・AWS Shield などのネットワーク保護サービスの設定）
- Task 5.2: ドメイン・DNS サービス・コンテンツ配信を設定する（Route 53 ホストゾーン・レコードの設定、Route 53 ルーティングポリシーの実装（ジオロケーション・ジオプロキシミティ）、Route 53 Resolver による DNS 設定、CloudFront と S3 オリジンアクセスコントロール（OAC）の設定、S3 静的ウェブサイトホスティングの設定）
- Task 5.3: ネットワーク接続の問題をトラブルシューティングする（VPC 設定の解釈（サブネット・ルートテーブル・ネットワーク ACL・セキュリティグループ）、VPC Flow Logs・ELB アクセスログ・WAF Web ACL ログ・CloudFront ログの収集と解釈、CloudFront キャッシュ問題の特定と修復、ハイブリッドおよびプライベート接続問題のトラブルシューティング）

【第6ドメイン：Cost and Performance Optimization】
- Task 6.1: コスト最適化戦略を実装する（コスト配分タグの実装、Trusted Advisor・Compute Optimizer・Cost Explorer を使った未使用・使用率低下リソースの特定と修復、AWS Budgets・請求アラームの設定、EC2 スポットインスタンス適用のためのリソース使用パターン評価、マネージドサービス活用機会の特定（RDS・Fargate・EFS））
- Task 6.2: パフォーマンス最適化戦略を実装する（パフォーマンスメトリクスに基づくコンピューティングリソースの推奨、EBS メトリクスの監視とパフォーマンス効率向上のための設定変更、S3 パフォーマンス機能の実装（S3 Transfer Acceleration・マルチパートアップロード）、RDS メトリクスの監視と設定変更（Performance Insights・RDS Proxy）、EC2 拡張機能の有効化（Elastic Network Adapter・インスタンスストア・プレイスメントグループ））
