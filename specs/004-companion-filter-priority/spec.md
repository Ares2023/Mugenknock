# 基礎知識(companion)問題のフィルタ優先順位と件数内訳表示

- 状態: 下書き
- 起票日: 2026-09-21

## なぜやるか

MLA（前提知識: ML）等、対応する基礎知識(オリジナル)資格を持つ公式資格では、
「基礎知識を含める」をONにすると出題プール自体には既に基礎知識側の問題が混ざる
（`includeCompanion`、specs/003-original-exam-blend）。未回答/不正解/ブックマーク
フィルタも技術的には既に基礎知識側の該当問題にマッチしている（`UserQuestionStats`が
userId単位でexamType不問のため）。

しかし実際の出題順序では、目標資格と基礎知識の問題が**ドメイン均等化により均等に混在**
してしまい、「まず目標資格の対象問題を解き切ってから基礎知識に入る」という利用者が
期待する優先度になっていない。また演習設定パネルの件数表示（例:「不正解を優先：32問」）は
合算数のみで、内訳（目標資格何問・基礎知識何問）が分からず、基礎知識を含めた結果
何が増えたのか利用者が把握できない。

- [x] ログインユーザー

ログインユーザーのみ。ゲスト境界に変更なし。

## 何を作るか

1. **出題優先順位の変更**: 未回答/不正解/ブックマークいずれかのフィルタがONの状態で
   「基礎知識を含める」もONの場合、同じフィルタ一致度（スコア階層）の中では
   **目標資格の問題を先に出題し切ってから、基礎知識側の該当問題で不足分を埋める**。
   目標資格側の対象問題だけで出題数が足りればそのセッションに基礎知識問題は
   1問も混ざらないことがある（正常な挙動）。
   対象: サクッと演習・演習（通常）・しっかり対策の3モード。模試は対象外（現状維持）。
2. **件数表示に内訳を追加**: 演習設定パネルの回答状況フィルタ（**指定なし／未回答／
   不正解／未正解**）・ブックマークフィルタ、それぞれの件数表示に、基礎知識分の内訳を
   併記する。「指定なし」（フィルタ未指定＝全問題が対象）も例外にせず合計問題数を表示する
   （現状「指定なし」は件数が空欄で何問が対象か分からない）。
   例: 「指定なし：120問（基礎知識30問）」「不正解を優先：32問（基礎知識8問）」
   対応する基礎知識資格が無い資格、または内訳が0問の場合は内訳を表示しない。

## 受入条件

- [ ] MLAを目標資格に設定し「基礎知識を含める」ONで「不正解を優先」フィルタを付けて
      サクッと演習を開始すると、目標資格(MLA)側の不正解問題が全て出題されるまで
      基礎知識(ML)側の不正解問題は出題されない（目標資格側の不正解問題数 <
      出題数の場合のみ、残り枠にML側の不正解問題が混ざる）
- [ ] 同条件で「演習」（Practice.tsx通常モード）・「しっかり対策」を実行した場合も
      同じ優先順位になる
- [ ] 演習設定パネルの回答状況フィルタ「指定なし」に合計問題数（基礎知識込み）が表示される
      （現状は空欄）
- [ ] 「基礎知識を含める」をONにすると、指定なし/未回答/不正解/未正解/ブックマーク
      各フィルタの件数表示に「（基礎知識N問）」の内訳が追加される
- [ ] 対応する基礎知識資格が無い資格（例: SAA）を選んでいる場合は、件数表示は
      従来通り内訳なしの合算数のみ
- [ ] 基礎知識側の問題に演習中に回答しても、目標資格側のドメイン別統計・予想スコアには
      従来通り算入されない（既存挙動を壊さない）
- [ ] 模試（ミニ模試含む）は本spec変更の影響を受けない（`includeCompanion`を渡さない
      既存挙動を維持）

## 対象外（やらないこと）

- 基礎知識問題を出題プールに混在させる仕組み自体の新規実装（`includeCompanion`は
  specs/003-original-exam-blendで実装済み。本specはその上の優先順位付け・表示のみ）
- 基礎知識側の問題を優先する比率設定・上限キャップ（今回は「目標資格を使い切ってから
  基礎知識で埋める」という単純な優先順位のみ。将来「常に一定割合を基礎知識に回す」
  ニーズが出たら別specで検討する）
- ドメイン別統計・予想スコアへの基礎知識分の算入（既存方針を維持し変更しない）

## 既存の不変条件との整合

- 出題プールの条件 `!isHidden && !!validityCheckedAt` を維持するか: はい（変更しない）
- ドメイン均等化（deficit round-robin）の方針に反しないか: 反しない。
  「目標資格を優先」を**フィルタ一致度より下・ドメイン均等化より上**の階層として
  scoreFnに組み込む形にする（詳細はplan.md）。目標資格内・基礎知識内それぞれの
  ドメイン均等化ロジックは変更しない。
- ゲスト/ログイン境界に反しないか: 反しない（対象はログインユーザーのみ、既存の境界通り）
- `correctAnswerIndices` を正準とする不変条件に触れるか: 触れない
