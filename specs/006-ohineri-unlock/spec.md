# おひねり（1日の演習上限と、100円での撤廃）

- 状態: 実装中（2026-10-05 要件の主要部分を確定。未決事項6〜10は公開前に決める）
- 起票日: 2026-10-05

## なぜやるか

- **目的は収益ではなく、決済システムを実際に作って動かしてみること。** 利用者は少なく、
  売上は期待していない。したがって「儲かるか」ではなく「安全に・小さく・壊さず決済が通るか」で判断する。
- 無料で困らないことが前提（製作意図: 初学者向けに軽く・シンプルに・質の高い問題を演習できる）。
  課金しない人の体験は、**日常の使い方ではほぼ変わらない**ことを守る。

## 何を作るか（現時点の合意）

1. **1日の演習上限: 30問。** 超えた分は、その日は解けない（翌日リセット）。
2. **「おひねり」100円（1回のみ）で、上限を恒久的に撤廃する。** 月額・更新・複数回購入は無い。
3. 課金しなくても、上限30問以内なら全機能が従来どおり使える。

## 受入条件

- [ ] 無課金のログインユーザーが、1日に30問まで回答でき、31問目から新しい演習を開始できない
- [ ] 日本時間 0:00 を過ぎると、回答数がリセットされる
- [ ] テスト決済（本番キーではない）で100円を支払うと、そのユーザーの上限が撤廃される
- [ ] 同じ決済通知が複数回届いても、購入が二重に記録されない
- [ ] 決済が完了していないユーザー・他人のアカウントに撤廃が反映されない
- [ ] 購入の事実はサーバだけが決める（画面操作やリクエストの書き換えで撤廃できない）
- [ ] ゲストには上限表示も購入導線も出ない
- [ ] 購入後にログアウト・別端末でログインしても撤廃が維持される
- [ ] 本番キーでの実決済は、最初に自分の1件で確認してから公開する

## 対象外（やらないこと）

- 月額課金・サブスク・複数回の購入・金額を選べる投げ銭
- 購入者向けの特典（問題の追加・バッジ・広告の削除など）
- ポイント・クーポン・紹介コードなどの周辺機能
- ゲストの利用制限（ゲストはローカルに累積を溜めない原則と衝突するため）
- アプリ版（Android/iOS）での課金（ストアの決済規約が別体系。未決事項参照）

## 既存の不変条件との整合

- 出題プール `!isHidden && !!validityCheckedAt`: 触れない
- ドメイン均等化（deficit round-robin）: 触れない
- ゲスト/ログイン境界: 決済・上限ともログイン専用。**ゲストを制限しないので、上限を避けたい人は未ログインで使える。** これは意図した「ゆるさ」として受け入れるか未決事項に挙げる
- 認証: 回答記録 `POST /sessions/:id/answers` は現状**ログイン検証なし**（body の userId を信用）。上限を厳密に効かせるなら見直しが要る（plan §認証 参照）
- 製作意図（軽く・シンプル・冗長な演出なし）: 購入案内は小さく・1回で閉じられる形にする

## 確定した決定（2026-10-05）

- **ゲストは上限なし・購入不可**（未決1 → A）。上限を避けたい人が未ログインで使えるのは許容する
- **アプリ版は別扱いしない**（未決2）。Android/iOS はストアにリリースしておらず、実態は「スマホのブラウザで開く」だけ。
  したがってモバイルも Web と同じ上限・同じ Stripe 決済でよい（ストア課金は不要）。
  ※ リポジトリの `android/` ディレクトリは存在するが、公開していないため対象外
- **模擬試験は上限対象外。通常演習は開始時に「残り問題数」へ切り詰める**（未決3・4）。ミニ模試も対象外
- **決済代行は Stripe Checkout（1回払い）**（未決5）
- **公開まで上限は発動しない。** 管理設定 `AppSettings.ohineri.enabled` が true になるまで、
  上限の判定も購入ボタンも出さない（実装を先に出しても利用者に影響しない）。決済キーが無ければ有効にできない

- **しっかり対策・苦手分析の解放を 30問 → 20問 に下げた**（2026-10-05）。1日の上限（30問）と解放条件が重なると、
  初日に頑張った人が「上限に達したのに、まだ解放されない」状態になるため。解放は上限より先に達する値にする
  （`FOCUSED_UNLOCK_THRESHOLD`、`Home.tsx` / `MyPage.tsx`）。今後、上限を下げるときは解放の閾値より大きく保つこと
- **おひねりの案内ページ `/aws/ohineri`** を新設し、「その他」の**一番下**のボタンから入る。ボタンはログイン中かつ機能が有効なときだけ出す。
  決済後の戻り先もこのページ（`?ohineri=success&session_id=…`）
