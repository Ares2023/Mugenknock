# オリジナル資格(前提知識)問題を公式資格の出題プールへ既定で混在

- 状態: 実装中（ローカルdev環境で受入条件を確認済み・develop検証環境での確認待ち）
- 起票日: 2026-09-16

## なぜやるか

「オリジナル」資格（ML/DB/NW/SEC）は AIF/MLA/AIP・DEA・ANS・SCS が前提とする
AWS非依存の基礎知識を問う独自カードだが、現状は**既存問題を複製して投入する運用**
（`CLAUDE.md` の Additional レベル節）になっている。

公式資格側の出題プールにも「AWSサービス非依存の一般的な概念」を問う問題が元々含まれており
（例: `AIF` の生成プロンプトには「実際のAIF試験の約40%はAWS非依存の一般的なAI・ML概念を問う」
という指示がある）、これがオリジナル資格の問題と内容的に重複し、**同じ知識を2箇所で別問題として
管理する二重管理**になっている。

これから重複を作らないようにし、公式資格を演習すれば前提知識(オリジナル)問題も
既定で混ざって出てくる形にすることで、二重管理を解消する。

## 何を作るか

### 1. 公式資格 ↔ オリジナル資格の対応関係を定義

| 公式資格 | オリジナル資格 |
|---|---|
| AIF / MLA / AIP | ML |
| DEA | DB |
| ANS | NW |
| SCS | SEC |

### 2. 通常演習（サクッと演習・しっかり対策・トレーニング画面の演習タブ）で既定混在

上記の公式資格を対象に演習を開始すると、**既定で**対応するオリジナル資格の問題も
出題プールに混ざる。オフにするフィルタ（トグル）を用意し、**既定はON（含める）**。

フィルタには「ドメイン別統計・予想スコアには反映されない」旨を明記する
（誤解を防ぐため）。

### 3. 模擬試験には適用しない

模擬試験（`ExamSetup.tsx` / `Practice.tsx` の模試タブ）は公式試験の出題数・時間を
模した体験のため、**今回は対象外**。公式資格の問題のみで構成する（現状維持）。

### 4. ドメイン別統計・苦手分析・予想スコアへの不算入

オリジナル資格の問題はオリジナル資格自身のドメイン体系（例: MLの「AI/MLの基礎概念」等、
AIFの「AIとMLの基礎」等とは別物）を持つ。混在出題で回答しても、**公式資格側の
ドメイン別統計・苦手分析・予想スコア(estimatedScore)には算入しない**
（オリジナル資格自身の統計には従来通り算入される）。

### 5. 出題数の均等化（ドメイン偏り是正）には参加させる

「まだ解いていないドメインを優先する」既存の deficit round-robin には、
オリジナル資格の問題も独立したバケットとして参加する（出題機会が偏らないようにする）。
公式資格のドメインとオリジナル資格のドメインを取り違えてバケット化しないこと
（後述の不変条件参照）。

## 受入条件

- [ ] AIF/MLA/AIP/DEA/ANS/SCS を対象にサクッと演習・しっかり対策・トレーニング画面の
      演習タブを開始すると、フィルタを変更しない限り対応するオリジナル資格の問題が混ざる
- [ ] 上記の演習設定画面に「前提知識(オリジナル資格名)を含める」トグルがあり、既定ON。
      OFFにすると混ざらない
- [ ] トグルの近くに「ドメイン別統計・予想スコアには反映されません」という説明がある
- [ ] 特定ドメインを選んで演習した場合（ドメイン絞り込みを使った場合）は、
      オリジナル資格の問題を混ぜない（公式ドメインとオリジナル資格の問題は対応しないため）
- [ ] 模擬試験（ExamSetup / Practice の模試タブ）の出題プールは変化しない
      （オリジナル資格の問題が混ざらない）
- [ ] 混在出題でオリジナル資格の問題に回答しても、公式資格側の
      ドメイン別統計・苦手分析・予想スコアの数字が変化しない
- [ ] 公式資格の演習中にオリジナル資格の問題へ回答した場合、その正誤データは
      オリジナル資格**自身**のドメイン別統計・苦手分析・予想スコアに正しく反映される
      （`src/utils/domainStats.ts` の `recordSessionDomainStats` を「回答した問題自身の
      examType」でグループ化するよう修正・2026-09-16追加）
- [ ] 演習設定モーダルの「未回答」等の件数表示が、混在時の母集団とズレない
      （`GET /users/me/question-status` がオリジナル資格分も合算して返す）
- [ ] 出題プールの偏り是正（deficit round-robin）で、公式資格のドメインNとオリジナル資格の
      ドメインNが同一バケットとして扱われない（取り違えない）

## 対象外（やらないこと）

- 既存の重複コンテンツ（公式資格側にある、オリジナル資格と内容が重複する問題）の
  洗い出し・削除。仕組みを作った後、別スコープで進める
- 模擬試験モードへの適用
- オリジナル資格問題の、公式資格ドメインへの再割当・マッピング
- ドメイン絞り込み演習でのオリジナル資格問題の混在（対応するドメインが無いため不可）
- ゲストへの機能開放可否の再検討（通常演習の一部なので自然に両方に適用されるが、
  ゲストの永続データ設計は変えない）

## 影響範囲

| 種別 | 影響 |
|---|---|
| 画面 | `src/views/Home.tsx`（サクッと演習・しっかり対策の設定モーダル）、`src/views/Practice.tsx`（演習タブの設定） |
| API | `GET /questions`（`includeCompanion` パラメータ追加）、`GET /users/me/question-status`（同上） |
| DynamoDB | スキーマ変更なし。既存 `Questions` の `examType`/`domain` をそのまま利用 |
| 夜間バッチ | なし（生成プロンプトの重複回避方針の見直しは別スコープ） |
| デプロイ | **Lambda も要デプロイ（dev+prod）** |

## 既存の不変条件との整合

- 出題プールの条件 `!isHidden && !!validityCheckedAt` を維持するか: はい
  （オリジナル資格側の問題にも同条件を適用してから合流させる）
- ドメイン均等化（deficit round-robin）の方針に反しないか: 反しない。ただし
  `domainBalancedOrder` のバケットキーを `domain`（数値）単独から `examType:domain`
  の複合キーに変更する必要がある（公式資格とオリジナル資格で `domain` のインデックスが
  別体系なのに同じ数値を使っているため、素のまま混ぜるとバケットが衝突する）
- ゲスト/ログイン境界に反しないか: 反しない。新規の永続データは増やさない
  （フィルタ設定は既存の `quickExercisePrefs_*` 等の枠に1フィールド追加するのみ）
- `correctAnswerIndices` を正準とする不変条件に触れるか: 触れない
